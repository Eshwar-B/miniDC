# MiniDC Architecture Documentation

MiniDC turns idle Linux and Windows laptops into mini datacenters by streaming disposable, isolated Ubuntu desktop virtual machines directly to a borrower's web browser.

---

## 2. Component Descriptions

### 2.1 MiniDC Control Server (`minidc-server`)
- **Technology:** Java 21, Spring Boot 3.3, Spring Security, Spring Data JPA, Flyway, PostgreSQL.
- **Role:** Centralized authority managing authentication (invite-code gated registration, JWT), compute node registry, capacity offers, lease state machine, scheduled health monitors, and Guacamole token generation.

### 2.2 MiniDC Node Agent (`minidc-agent`)
- **Technology:** Java 21, Spring Boot (non-web), Spring WebSocket client, Jackson.
- **Role:** Background daemon operating on lender machines. Connects outbound to the control server, continuously reports telemetry and health metrics, validates resource limits, and commands hypervisors to provision and destroy ephemeral virtual machines.

### 2.3 Web Interface (`minidc-ui`)
- **Technology:** React 18, Vite, TypeScript, React Router.
- **Role:** Single-page user portal for borrowers (browsing offers, requesting leases, launching browser desktop) and lenders (registering nodes, configuring limits, approving incoming requests, emergency kill switch).

### 2.4 Remote Desktop Gateway (Apache Guacamole)
- **Technology:** `guacamole/guacamole` and `guacamole/guacd` containerized via Docker Compose.
- **Role:** Translates client browser WebSocket/HTTP display traffic into guest RDP protocol sessions. Authenticates via signed JSON payloads generated by the control server.

## 3. Core Data Flow: Lease Lifecycle

1. **Offer Publication:** Lender sets max RAM, CPU, disk, hours, and optional daily windows on an online node.
2. **Lease Request:** Borrower selects an offer and requests specific resources $\le$ offer maximums.
3. **Approval:** Lender manually approves or auto-approval rules trigger.
4. **Provisioning:** Server commands Agent via `CREATE_VM`. Agent checks local safety headroom, creates a copy-on-write disk overlay, generates cloud-init configuration with credentials, and boots the VM headless.
5. **Ready:** Once xrdp is accepting connections, Agent informs Server (`VM_READY`) with the host port.
6. **Streaming:** Borrower clicks "Open Desktop", Server creates signed Guacamole launch URL, Guacamole bridges RDP session to browser.
7. **Destruction:** At lease expiration or manual cancellation, Server sends `DESTROY_VM`. Agent forcibly terminates the VM, wipes the ephemeral overlay disk, tears down firewall rules, and confirms deletion.
